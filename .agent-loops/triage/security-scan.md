# Flick security scan

Date: 2026-09-18
Repo: `/Users/abhijitsr/flick`
Scope: read-only review of `Sources/`, `Resources/Info.plist`, `Scripts/package-app.sh`, `Makefile`. Design notes in `docs/design.md` used only as threat-model context.
Not in scope: binary reversing of `dist/Flick.app`, runtime TCC prompts, notarization paperwork.

Threat model: unsandboxed `LSUIElement` agent with clipboard history, Carbon hotkey, optional Accessibility (HID paste), Finder/System Events Automation, FSEvents on Desktop/Documents/Downloads, login-item persistence, ad-hoc codesign.

## Controls that look sound

- AppleScript sources are **string literals**, not interpolated with paths or query text. No `osascript` shell wrapping.
- `pmset` is `/usr/bin/pmset` + fixed `["sleepnow"]` via `Process` (no `/bin/sh`).
- Calculator is a tiny arithmetic parser (`MiniMath`), not `NSExpression` format strings.
- `URLRouter` only accepts `http://`, `https://`, or a dotted host rewritten to `https://`. No `javascript:`, `file:`, `smb:`.
- Accessibility is optional (`AXIsProcessTrusted`); paste is hidden when untrusted. Usage string exists in Info.plist.
- Global `NSEvent` monitor is **mouse-down only** while the HUD is visible (dismiss). Carbon `RegisterEventHotKey` is not a keylogger.
- JSON cache uses `Codable` + `JSONDecoder`, not `NSKeyedUnarchiver`.
- Store writes go through a temp file + `replaceItemAt` (crash-safe). Kill list excludes Flick’s own bundle id and non-`.regular` apps.

## Findings

### 1. HIGH — Concealed pasteboard UTI is the wrong string

**Location:** `Sources/FlickCore/Catalog/Item.swift:80-85`, used by `ClipboardSource.ingest` at `ClipboardSource.swift:54-56`. Same misspelling in `docs/design.md` and `FlickSelfTest`.

```80:85:Sources/FlickCore/Catalog/Item.swift
public enum PasteboardPrivacy {
    public static let concealedType = "org.nspasteboard.concealedType"

    public static func isConcealed(types: [String]) -> Bool {
        types.contains(concealedType)
    }
}
```

**Impact:** The community UTI (nspasteboard.org), used by 1Password, Bitwarden, Apple Passwords, KeePassXC, etc., is `org.nspasteboard.ConcealedType` (capital `C`). `contains` is case-sensitive. Password-manager copies still have `public.utf8-plain-text`, so Flick records them, shows them in the HUD (including empty-query “top clip”), and writes them to disk.

The test only asserts the misspelled constant matches itself, so it cannot catch this.

**Fix:** Compare case-insensitively against the real UTIs, and skip transient/auto-generated clips too:

```swift
private static let skip: Set<String> = [
    "org.nspasteboard.ConcealedType",
    "org.nspasteboard.TransientType",
    "org.nspasteboard.AutoGeneratedType",
]
static func shouldSkip(types: [String]) -> Bool {
    types.contains { skip.contains($0) }
}
```

Update the self-test to assert `org.nspasteboard.ConcealedType` is skipped and `org.nspasteboard.concealedType` is not relied on.

### 2. HIGH — Clipboard history stored as world-default plaintext JSON

**Location:** `ClipboardSource.swift:54-65` → `Store.saveClipboard` `Store.swift:99-145`.

- Last 20 strings, full body (only the HUD title is clipped to 80 chars).
- Pretty-printed JSON at `~/Library/Application Support/dev.abhijitsr.flick/clipboard.json`.
- `Data.write` / `replaceItemAt` never set POSIX mode. Default umask → typically `0644`.
- No encryption, no Data Protection, no TTL, no max item size.

**Impact:** Tokens, private keys, and any clip that lacked a concealed marker (browser password fields, `cat ~/.ssh/id_rsa`, Notes, Slack) survive reboot. On a shared Mac, group-readable Application Support + `0644` lets other local accounts scrape the file. Crash reports / Time Machine / unencrypted disks copy the same plaintext.

**Fix:**

1. `chmod 0700` the store root and `0600` every written file (`setAttributes([.posixPermissions: 0o600], …)` after replace).
2. Do not persist clipboard by default; keep it in memory, or encrypt at rest (Keychain / CryptoKit with a Keychain key).
3. Cap item size (e.g. 16 KiB) and drop clips older than a short TTL.
4. When Flick itself copies (history paste / copy path), mark the pasteboard with `ConcealedType` and/or `TransientType` so other managers do not re-record.

### 3. MEDIUM — HID Cmd+V paste can hit the wrong app and re-publishes secrets

**Location:** `Actions.swift:81-88`, `185-195`, `179-183`.

```81:88:Sources/FlickCore/Actions/Actions.swift
        case .paste:
            guard let text = item.text else { return .fail("Nothing to paste") }
            copy(text)
            previousApp?.activate()
            DispatchQueue.main.asyncAfter(deadline: .now() + 0.05) {
                pasteKeystroke()
            }
```

```185:195:Sources/FlickCore/Actions/Actions.swift
    private static func pasteKeystroke() {
        guard AXIsProcessTrusted() else { return }
        let source = CGEventSource(stateID: .hidSystemState)
        let keyV: CGKeyCode = 9
        let down = CGEvent(keyboardEventSource: source, virtualKey: keyV, keyDown: true)
        let up = CGEvent(keyboardEventSource: source, virtualKey: keyV, keyDown: false)
        down?.flags = .maskCommand
        up?.flags = .maskCommand
        down?.post(tap: .cghidEventTap)
        up?.post(tap: .cghidEventTap)
    }
```

**Impact:**

- `copy(text)` overwrites `NSPasteboard.general` **without** Concealed/Transient markers, then a 50 ms later global HID ⌘V is posted to whoever is frontmost — not bound to `previousApp`.
- If activate fails, is slow, or the user clicks away, the clip (possibly a password from finding 1) lands in the wrong app (Messages, a password field, a terminal).
- The previous clipboard is destroyed; the secret remains on the general pasteboard for the next ⌘V.

**Fix:** After `activate()`, wait until `NSWorkspace.shared.frontmostApplication == previousApp` (timeout then abort). Post the keystroke only then. Restore the previous pasteboard after paste (or use a private pasteboard + AX `insertText` targeted at the previous app’s focused element). Mark Flick’s write as transient/concealed.

### 4. MEDIUM — Login item re-registers every launch; default is on

**Location:** `Store.swift:8-12` (`Prefs.optionSpace.loginItemEnabled = true`), `AppDelegate.swift:29-32`.

```29:32:Sources/FlickCore/App/AppDelegate.swift
        let prefs = store.loadPrefs()
        if prefs.loginItemEnabled {
            _ = LoginItem.setEnabled(true)
        }
```

**Impact:** First launch with no `prefs.json` silently calls `SMAppService.mainApp.register()`. If the user later disables Flick in System Settings → Login Items without toggling Flick’s menu, the next launch **turns it back on**. Persistence without a matching user gesture on that launch.

**Fix:** Default `loginItemEnabled` to `false`. On launch, **read** `SMAppService.mainApp.status` into prefs; do not call `register()` unless the user just enabled it in Flick’s menu. Never re-register because a stale JSON flag is true.

### 5. MEDIUM — Force-kill and Empty Trash have no confirmation; kill trusts a stale PID

**Location:**

- Kill default for `kill:` command rows: `CommandSource.swift:78-90`, `Actions.swift:89-92`, `164-173`.
- `forceTerminate()` with no bundle-id check: `Actions.swift:115-130`.
- Empty Trash: `Actions.swift:141-147`.

**Impact:** Typing `kill` and pressing Return force-quits the first `.regular` running app (unsaved documents gone). `NSRunningApplication(processIdentifier:)` is used without verifying `app.bundleIdentifier == item.bundleIdentifier`; a recycled PID can kill a different process. Empty Trash is immediate once Finder Automation was granted once.

This matches `docs/design.md` (“No confirmation dialog”) but is still a destructive-control gap.

**Fix:** Kill/Empty Trash should not be the unlabeled default of Return without a modifier, or require a one-shot confirm in the HUD. Before `forceTerminate`, require `app.bundleIdentifier == item.bundleIdentifier` (and still-running). Drop the PID-only branch.

### 6. MEDIUM — “Open folder” / file open does not constrain the path

**Location:** `Routers.swift:107-119`, `SearchEngine.swift:79-96`, `Actions.swift:98-107`, cache load `Catalog.swift:31-53`.

- Any query starting with `/` or `~` becomes an Open folder row whose `path` is passed to `NSWorkspace.shared.open`. That launches apps, executes `.command` files, and opens `~/.ssh/id_rsa`, not only folders.
- Indexed file rows are opened by stored path with no check they still live under Desktop/Documents/Downloads (symlink / replace TOCTOU after scan).
- `catalog-cache.json` is trusted on startup: extra `CachedFile.path` values appear in the HUD with no root allowlist.

**Impact:** User-typed paths are partly intentional, but the row title lies (“Open folder”). A poisoned or stale cache (writable by any same-user process; default file mode `0644`) can plant sensitive paths into search results.

**Fix:** Resolve symlinks (`URL.standardizedFileURL` / `resolvingSymlinksInPath`). For catalog files, refuse to open unless the resolved path is still under `FileSource.defaultRoots()`. For the path router, only `open` if the URL is a directory; otherwise reveal in Finder. On cache load, drop entries outside those roots. Keep store files `0600`.

### 7. LOW — Ad-hoc sign, no hardened runtime, no notarization

**Location:** `Scripts/package-app.sh:29-30`.

```
codesign --force --sign - --identifier dev.abhijitsr.flick "$APP"
```

**Impact:** No `--options runtime`, no timestamp, no entitlements. `DYLD_INSERT_LIBRARIES` works when launched from a shell. Gatekeeper will nag if the app is copied across machines; local tampering of `dist/Flick.app` is trivial. Accepted as v1 in the design spec, still a packaging hole if this binary is handed to anyone else.

**Fix:** Sign with a Developer ID, `--options runtime`, timestamp, and notarize. Hardened runtime will also need `com.apple.security.automation.apple-events` if Apple Events stay.

---

### 8. LOW — `http://` URLs are opened as-is

**Location:** `Routers.swift:123-126`, `Actions.swift:98-101`.

**Impact:** User-typed `http://` (including RFC1918 / localhost) is opened in the default browser. No custom-scheme issue. Residual phishing / cleartext.

**Fix:** Prefer rewriting `http://` → `https://` except for localhost/loopback, or show a scheme badge and require ⌘Return for cleartext.

---

### 9. LOW — Unbounded clipboard payload

**Location:** `ClipboardSource.swift:57-64`.

**Impact:** A multi-megabyte copy is stored 20× in RAM and JSON (DoS / swap leak), and is painted into the HUD title path. Not a sandbox escape.

**Fix:** Reject clips over a small byte limit before insert.

## How to verify

1. **Concealed UTI:** Copy a password from 1Password/Bitwarden. Inspect `NSPasteboard.general.types` (expect `org.nspasteboard.ConcealedType`). Open Flick on empty query — the password must **not** appear. Confirm `clipboard.json` does not contain it. Repeat with a dummy type `org.nspasteboard.concealedType` only, to prove the old check was wrong.
2. **Disk perms:** `ls -l ~/Library/Application\ Support/dev.abhijitsr.flick/` — expect `0700` dir / `0600` files after the fix; today expect `0644` JSON.
3. **Wrong-target paste:** Grant Accessibility. Copy a unique token into Flick history. Switch to TextEdit, invoke paste from Flick, and in the 50 ms window click Messages. Token must not appear in Messages after the fix.
4. **Login item:** Enable Flick, disable it only in System Settings Login Items, relaunch Flick. It must stay disabled.
5. **Kill PID:** Open a throwaway app, note PID, force-quit it, start another app that may reuse the PID, keep an old Kill row if possible — Flick must refuse.
6. **Path allowlist:** Type `~/.ssh` and Return — should reveal, not open keys. Plant `"path": "/etc/passwd"` in `catalog-cache.json`, relaunch — row must be dropped.
7. **Codesign:** `codesign -dv --verbose=4 dist/Flick.app` — today `adhoc`, no runtime; after fix `runtime` + Developer ID.

Existing self-test (`make test`) does **not** cover 1–6 except a tautological concealed-string check.

## Blockers

None for this report. No source was modified. Runtime TCC dialogs and live password-manager pasteboard types were not exercised on-device in this pass; finding 1 is from the string literal vs the published UTI.

## Residual risk

Flick is an unsandboxed, always-on agent. Even after the fixes above:

- **Automation is coarse.** Finder (Empty Trash) and System Events (Lock, Dark Mode) grants allow *any* Apple Events to those targets, not just the three static scripts. A replaced `Flick` binary can keystroke via System Events **without** Accessibility.
- **Accessibility, once granted, is HID-level input.** Paste must stay narrowly targeted; there is no way to make global AX “safe” against a malicious build.
- **Desktop/Documents/Downloads indexing** will surface secrets the user stored as ordinary files (`credentials.json`, `server.pem`). Hidden dotfiles are skipped; everything else is searchable and openable.
- **Clipboard historians cannot be perfect.** Web vaults and Terminal copies often omit ConcealedType. Memory-only history + 0600 + skip-list is the realistic bar, not “no secrets ever.”
- **Ad-hoc local builds** remain Gatekeeper-unsigned until Developer ID + notarization. Login-item + AX + Automation on an unsigned agent is a high-value persistence target.
- **Shoulder surfing:** empty-query HUD shows the current clipboard in plaintext. Mask concealed/high-entropy clips even when they are allowed in memory.

v1 explicitly opted out of sandbox and notarization; those remain the largest structural limits, not code bugs.
